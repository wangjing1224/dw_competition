# 报告模板与填写要求

本节约定当前文件的新版内部 Markdown 草稿格式，不是最终报告正文。通过通用报告工具增量维护一份文件，成功保存内容是唯一成果；不要在普通回复中重写报告或输出 JSON。路径、身份、规则骨架由系统维护。正式阅读稿的章节、名称、编号、统计及原文摘录由代码组装，不需要你再写一份。

## 内容与填写顺序

1. 读取当前骨架，按输入规则逐条核验；保留类别标题、类别代码、规则 ID 和顺序，不自行新增、删除、重分类。
2. 及时保存已完成的判断，后续新事实修订同一条。每条分别写结论、实际发现、判断说明和必要的复核建议。
3. 全部明细形成后，归纳短总结和重点问题；修改明细时同步修正受影响的重点与总结。
4. 保存具体报告标题、总体总结、重点问题及全部规则结果，消除占位后完成。最终聊天回复不是报告。

标题为1～120字的单行纯文本一级标题，结合已知项目、采购对象或文件性质体现“审核报告”；不写固定行业名、不编造身份或业务编号、不在标题塞结论。总体总结建议约150～300字，回答主要发现、风险和待核实事项，不逐条重复完整明细。重点通常3～6项，少则如实少写，无问题时不凑数。这是表达目标，不以硬截断丢失关键条件、单位或不确定性。

## 内部格式

以下是局部示意，尖括号为说明占位，实际填写必须使用当前骨架与真实信息。不要在整篇外包代码围栏。新版没有“分类总结”。

```markdown
# 〈请填写报告标题〉

## 总体总结

〈主要结果、重要差异与判断边界〉

## 重点问题

### 问题 1：〈简短问题标题〉

关联规则：〈真实规则ID，多个用顿号分隔〉

问题概述：〈依据所关联明细归纳，不重复写一份建议〉

## 〈骨架中的类别名称〉（〈类别代码〉）

### 〈rule_id〉

结论：〈符合、不符合、风险、人工复核，选一个〉

实际发现：〈已读材料所载的事实、缺口或不确定性〉

审核说明：〈解释事实与规则要求的关系，不写内部思维过程〉

复核建议：〈具体、可执行且不越权的下一步；无则省略整行〉
```

每条“结论：”“实际发现：”“审核说明：”必须各出现一次且顺序固定，使用中文冒号。后两项可多行 Markdown、段落或列表，不另造标题。复核建议和来源行紧随其后，每种最多一次。可选字段无值时省略，不写空数组、null、“无”或虚构占位。

规则要求、类别、重要程度来自冻结规则，代码补齐，不重复抄写全套要求。自由正文用文件名称和自然语言，内部 rule/file/project/bidder/audit ID 只用于结构化的规则标题、关联规则和来源行。保留真实业务编号，不把文件技术编号当作项目编号。

## 事实、判断与建议

- 实际发现只陈述所读事实和边界；审核说明解释这些事实为什么支持本项结论。二者不是两次复述规则要求。
- 符合：可靠事实支持满足适用要求；不能把投标声明或资料摘要等同于原件真实性核验。
- 不符合：有明确适用要求及足以证明不满足的事实。未检索到、后文尚未读到、图片模糊本身不等于未提交或违反。
- 风险：有具体疑点或潜在影响，但不足以认定违反；不能自行添加否决条件。
- 人工复核：已完成本次核验后，因明确材料缺口、读取限制或冲突仍无法可靠判断；不是尚未开展工作的替代。
- 不符合、风险、人工复核项应给出具体复核建议，说明核对什么以及依据。建议不表示法律上允许补交、已证明材料真实有效或必然合格；不超出规则判定废标、中标或造假。
- 符合项可以简短，无具体下一步就省略建议。不要为等长扩写，必要数值、单位、适用范围与限定条件必须保留。

例如，若招标要求同一起算点90日而投标函承诺60日：实际发现写“投标函载明有效期为自投标截止日起60日”；判断写“比要求少30日，不满足本项要求”；建议写“核对投标承诺期限与招标要求，确认该差异的处理方式”。如果只是图片无法辨认期限，应写人工复核和待核事项，不能照搬不符合结论。示例不能当作当前文件事实。

## 重点问题与处理建议

“重点问题”内按“问题 1：标题”“问题 2：标题”连续编号，各块仅填写关联规则和问题概述。必须关联当前文件的真实规则，至少一条关联结论不是符合；同块不重复关联。允许多条规则归纳一个问题，不把问题项数当成独立缺陷数。

概述不得比关联结果更绝对：人工复核不是已证实不符合，疑点不是已确认造假。处理建议只在每条规则的“复核建议”写一次，代码在重点章节按关联复用，不再写重点级建议字段。重点不是全部问题清单，完整规则和建议由明细保留。

没有重点问题时，该节只写“无重点问题。”，不能同时保留问题块或占位。

## 可选来源

来源行只登记真正支撑本项判断、已经实际读取且在授权范围内的键。每种最多一行，多个值用中文顿号“、”分隔，不加反引号、描述或代码围栏。

- 招标片段：检索实际返回并读取的招标原文 chunk_id。
- 投标片段：检索实际返回并读取的当前投标文件 chunk_id。
- 资料片段：子 Agent 核验正文引用且该子会话实际读取过的资料 chunk_id。
- 图片来源：主 Agent 实际查看，或子 Agent 正文引用且实际查看过的真实图片路径。

系统通过读取账本取得冻结文件名、已有位置与解析原文，不要求你重抄摘录、编造页码或生成新引用 ID。直接依据 Human 输入正文可以不填片段 ID，不为凑来源检索或伪造文件级片段。读过摘要、看到路径或存在关系不等于已读原件；图片没有文字 quote 时不编造 OCR。缺少引用记录也不等于没有读过材料。

## 草稿与完成

- 未完成块可暂留系统的“待填写。”；已填规则必须具备三个必填字段，非法来源即使在草稿也不可保存。
- 分批阅读时，未读到不能推断整份文件没有；全部原文范围处理结束前不能宣称审核完成。
- 最终须覆盖全部冻结规则，每条一次；标题、总体总结、重点问题及规则块无占位，关联和来源真实有效，重点与明细一致。
- 有依赖的核验必须等工具结果返回后再写入；不要同时派发核验和假定其结果的报告写入。
- 有限轮次内及时增量保存，收到最后工具轮提醒优先保存；普通回复、压缩交接或未保存判断不替代落盘。
- 保存失败、轮次耗尽、模型或网络错误属于执行异常，不补写业务“人工复核”来凑齐完成。未完成则保留草稿并如实说明。
