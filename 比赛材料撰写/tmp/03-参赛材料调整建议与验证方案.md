# 基于 2026 年市场的参赛材料调整建议与验证方案

编制日期：2026 年 10 月 3 日。性质：内部写作与验证建议，尚未作为已完成成果写回 v1.0。保留“跨行业通用审核平台”的产品定位，电力采购仍为首批验证样本。

## 一、当前需要回答的核心问题

评委可能追问：强通用 Agent 配好审核指令、文件工具和报告模板，能否完成同样的工作？如果能，为什么需要这个系统？

当前代码能证明平台实现了业务流程、版本与来源管理、工具约束和报告交付，尚不能证明审核更准确、总成本更低或复核更省时。材料应把这些优势写成有明确验证方法的目标，并优先展示已核实的机制和真实案例。

“全场景”表达架构适用范围，不单独承担创新性论证；“多智能体”说明组织方法，是否产生性能收益由对照结果决定。现有通用 Agent 与垂直产品的公开能力见 [市场报告](01-2026市场与竞争调研.md)及[来源索引](02-一手来源与证据索引.md)。

## 三、可用于改稿的表述草案

以下是备选段落，可结合相应附件字数裁剪；其中尚未开展的验证均使用计划语气。

### 1. 背景与问题定义

2026 年，招投标领域人工智能应用已进入政策推动、产品供给与项目采购并行阶段。通用智能体和专业招采软件已能参与文件解析、要点核对和报告生成，新的应用要求集中于复杂材料下的判断质量、跨项目适配、依据复核与持续交付。标智通围绕“项目要求—投标响应—支撑证据”组织审核，将通用模型能力纳入有版本、有范围、可回查的业务流程，并通过强通用智能体对照和跨场景实验评价实际增益。

来源依据：S01、S03、S04、S06、S09，详见[索引](02-一手来源与证据索引.md)。最后一句为本项目定位及拟验证目标，不是市场来源给出的结论。

### 2. 创新与差异化

本项目围绕材料审核的可复核交付设计协同机制：动态提取并确认项目规则，以具体核验事项连接投标响应与支撑资料；冻结任务所用版本，登记工具实际返回的来源，对规则覆盖、引用合法性和报告结构进行程序校验。上述机制已形成原型，其在关键风险发现、证据支持、完整产出和人工复核投入方面的增益，将通过强通用智能体及共享工具单智能体对照验证。平台保留跨行业通用核心，专业适配范围按样本逐项说明。

需要避免将“引用合法性”写成“证据必然足以支持结论”，也不要将“覆盖已抽取规则”写成“保证招标要求无遗漏”。

### 3. 市场竞争

竞争既来自具有客户和业务系统积累的招采软件厂商，也来自按次使用的审标工具、通用智能体及客户自行配置的审核流程。项目拟以明确范围的材料核验切入，通过真实样本比较审核质量、配置与复核工时、完整产出率和总成本。独立工作台服务直接使用需求，模块化接入作为后续交付方向；试点优先验证使用者、验收人和预算归属，不以采购总额推算软件收入。评测样本、错误分类和适配经验将作为持续积累的能力。

### 4. 对照实验

以人工复核基准评价三组方案：强模型配合完整指令及文件工具的通用智能体；共享本项目解析、检索和校验能力的单智能体；当前多智能体完整流程。分别比较相同人工确认规则下的审核，以及从原始招标材料开始的端到端处理。统一资料权限、输出要求和预算口径，计入准备、建库、失败重试及人工复核，报告关键风险召回、提示精确率、证据支持、完整产出和总成本；另以跨行业同类任务测量适配工作量。

## 四、公平且能决定产品方向的验证方案

### 1. 三组方案各回答一个问题

| 组别 | 配置 | 主要回答 |
| --- | --- | --- |
| A：强通用 Agent | 当前强模型、经开发集调优的业务指令、全部授权原件、检索/看图/计算/持续编辑工具、合理多轮预算；允许自主规划、回查及修订 | 用户使用现有通用 AI，能否直接得到可用结果？ |
| B：公共工具下的单 Agent | 尽量保持同一底座，接入本项目解析、检索、版本和产物校验能力；不启用主子核验分工 | 专用工具与程序约束提供了多少增益？ |
| C：当前完整平台 | 当前规则整理、资料入库、主审核和证据子智能体流程；保留全部执行记录 | 分工设计是否进一步改善质量或成本？ |

A 与 C 比较产品替代关系，B 与 C 检验主子分工。人工审核用于建立基准及计算工时参照，不应把单个人的首次意见直接当作无误真值。可访问的商业审标产品可作为附加 D 组；必须取得材料上传授权，且按真实使用范围比较。本轮未向任何第三方上传项目材料。

底座模型无法完全统一时，分别报告“同模型架构比较”和“用户实际可选产品比较”，不能把两类实验混为一项多智能体增益。先确定模型、版本和日期，再锁定测试集。

### 2. 测试集与问题类型

先用少量开发样本调试，再保留未用于提示词修改的测试集。样本规模、重复次数及验收阈值为【待确定】，不能用几份成功演示推断全行业可靠性。电力材料验证核心链路，另用非电力场景的同类任务检验迁移；不以新行业的新任务混淆迁移原因。

| 样本类型 | 检验重点 |
| --- | --- |
| 条件明确、证据集中的普通项目 | 简单任务上系统是否引入不必要成本；也要纳入没有问题的合格材料检查误报 |
| 条件分散于招标正文、附件和澄清文件 | 是否漏抽或误用要求，能否处理适用范围和版本变化 |
| 合同、验收、证书需要联合支持同一事实 | 跨材料支持是否充分，是否混淆主体、对象、日期、编号与阈值 |
| 表格、扫描页和图片含关键参数 | 解析与视觉读取错误如何影响最终判断 |
| 证据不足、相互矛盾或无法辨认 | 能否恰当交人工复核，避免无依据认定符合或不符合 |
| 长材料、多个任务或运行中途失败 | 规则检查及报告是否完整，失败是否可见，补审需要多少代价 |

使用真实且有代表性的困难案例；人工构造样例仅作为专项压力测试，单独报告。外部证书验真、围串标认定、自动评分等当前能力外任务不混入已支持任务的承诺范围。

### 3. 规则抽取和审核分开评价

第一阶段由业务人员标注应审要求，检查规则抽取的遗漏、误抽和条件保真。第二阶段给各组相同、经确认的规则，评价审核本身。第三阶段从同一批原件开始端到端处理，统计上游遗漏的传播。

规则基准须保留来源、主体、标段、时间、单位、阈值、例外与后果；争议由复核人员裁决并留档。测试期间不能根据某组输出临时降低基准要求。多次出现的同一业务问题要合并计数。

### 4. 指标与成本口径

| 指标 | 口径与注意事项 |
| --- | --- |
| 关键风险召回率 | 正确检出的关键风险事项／人工基准中的关键风险事项；同时给出分子、分母和原始个数 |
| 风险提示精确率 | 经复核成立的问题／输出为不符合或风险的问题；不把“转人工”混入该分母 |
| 证据支持率 | 按规则级结论抽检，检查所引原文及联合证据是否充分支持判断；来源能打开与判断被支持分别统计 |
| 完整产出率 | 对预先确定应进入审核的全部文件计算；超时、保存失败和缺项均不能从分母剔除 |
| 人工复核与总工时 | 包括材料整理、规则确认、资料入库校核、结果回查、纠错及补审；分开记录首次使用与重复项目 |
| 完整任务成本 | 模型、解析/OCR、检索和部署分摊，另记录人员成本；计入失败重试与子会话，不只报主模型花费 |
| 适配工作量 | 新场景所需代码修改、规则校核、术语配置、样本标注及业务人员投入，分别记录 |

给 A 组充分指令和合理工具；共同报告要求采用业务字段与可追查来源，不要求基线生成本项目内部专有 ID。比较同预算下的质量，并记录达到相近质量所需的成本。结论送业务人员盲评，保存运行原始记录；不要只挑最佳一次。

### 5. 根据结果决定主张

| 观察结果 | 合理的下一步 |
| --- | --- |
| C 相比 A、B 有稳定质量增益，成本可接受 | 可以重点论证事项协同的贡献，并展示收益集中的任务类别 |
| B、C 优于 A，但 B 与 C 接近 | 突出工具约束和业务交付；简化无收益的分工，减少多智能体作为性能卖点 |
| 三组质量接近，平台明显减少准备或复核投入 | 产品价值可围绕组织流程、使用便利和持续交付成立，需给出实际工时证据 |
| A 相同或更好，且总成本更低 | 下调独立平台的优势主张，考虑技能/插件、专用校验组件或更具体业务任务；先找证据再扩建 |
| 只有特定复杂任务体现优势 | 收敛首发任务范围，保留通用架构，不宣传已覆盖所有场景 |

## 五、首发市场选择与访谈提纲

以下为待验证候选，尚未替用户确定客户或商业路线。

| 候选 | 首单可以交付什么 | 进入前最需要确认 |
| --- | --- | --- |
| 投标企业的提交前自查 | 本次响应差异、资格与业绩证据问题清单 | 是否愿意提供原件；已有 AI 使用效果；资料维护投入能否重复摊销 |
| 代理或咨询机构的内部预审 | 多项目审核清单、证据定位和可交接报告 | 哪个岗位复核、减少哪项重复劳动、怎样形成验收与预算 |
| 企业采购中心的固定任务辅助审核 | 高频资格、业绩或参数响应审核 | 能否取得真实样本与业务基准；系统接入和保密要求是否可满足 |
| 招采系统服务商的组件接入 | 规则配置、证据回查或报告模块 | 对方是否已有同类能力，愿意购买的缺口是什么，接口和支持责任如何划分 |

优先按能获得的真实任务、验收人和付费条件选择试点。独立工作台通常更便于验证当前原型；平台接入存在真实需求，但本项目尚需补齐鉴权、调度等交付能力。这里的判断来自代码与采购案例综合分析，并非已完成客户调研。

访谈时用同一份真实任务核实以下事项，不直接询问笼统的“是否看好 AI”。

1. 上一次审核由谁完成，材料多少，哪一步最耗时，如何判断完成？
2. 已使用哪些通用 AI 或招采产品？哪些问题仍需人工解决？
3. 哪类漏检或误报会使结果不可用，复核人需要看到什么依据？
4. 材料、模型和接口可以怎样使用，规则变化由谁维护？
5. 一次试点交付哪些成果、由谁验收、预算属于哪个部门？
6. 总成本和复核工时改善到什么程度，才愿意继续使用或付费？

记录结果时区分事实、意见、使用意向和付费承诺；没有合同或付款证据，不写成已落地客户。公开挂牌价用于了解计价方式，不代替访谈和成本测算。

## 六、对获奖竞争力的重新判断

目前可以成立的是：作品有具体业务对象和较完整的实现，方向与实际采购需求相关。尚不能成立的是：相较 2026 年强通用 Agent 或直接竞品已经具有明确性能优势。

市场调研提高了写作的准确性，也提高了验证门槛。参赛叙事应围绕一个有业务分量的案例，解释为什么难、平台采取什么可核查机制、与强替代方案相比改善了什么，以及仍有哪些失败边界。获奖与长期商业壁垒是不同问题；当前证据不支持给出获奖概率或等级预测。
