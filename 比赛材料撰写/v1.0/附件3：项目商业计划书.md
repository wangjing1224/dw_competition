## 一、项目方案概述（不超过200字）

标智通面向货物、工程、服务等招投标场景，将项目要求、投标响应与支撑证据贯通，提供多智能体协同审核、问题定位和可复核报告。平台以通用文档处理与审核引擎为核心，动态生成项目规则，独立组织投标方资料，按文件配置审核依据，使不同业务共用产品能力。项目已形成软件原型，电力采购为首批验证样本，拟通过独立工作台与嵌入式模块服务采购单位、代理机构和平台运营方，将重复查阅转化为规则与证据驱动的辅助审核。

## 二、项目团队（不超过200字）

团队由【待填】名成员组成，专业背景、项目经历及指导支持情况为【待填】。按工作职责分为项目统筹、算法与文档处理、后端与数据管理、前端与交互、业务验证与产品转化，可由成员兼任。团队围绕需求、研发、测试、交付建立分工与交叉复核机制，负责原型迭代、样本整理和产品化准备；拟引入招采业务人员参与规则审阅与结果评测，具体安排为【待填】。人员姓名、单位及可识别经历按匿名评审要求另表登记，不在本正文披露。

## 三、项目产品（服务）化（不超过2000字）

### 1.项目产品（服务）特性

标智通提供一套随项目材料变化的通用审核产品。行业差异主要由招标文件、技术要求、业务规则和支撑资料表达，文档处理、检索核验、智能体协作及报告生成共享同一核心。产品面向招投标材料的响应性与证据一致性检查，帮助使用者把时间集中到关键差异、疑点和专业判断。

**项目规则动态生成。** 系统从招标文件及附件整理项目简介和审核规则，按格式、资格、商务、技术、业绩能力、一致性风险分类，保留要求、重要程度、核验方式和来源，支持人工修订。新项目通过导入材料形成自己的审核依据，无须为每个行业重写一套程序；相近项目可借鉴规则组织经验，具体条件与适用版本仍逐项确认。

**资料组织独立复用。** 投标方资料库独立于招标项目，保存逐文件简洁摘要、详细摘要与直接关联。简洁目录帮助主智能体选择有关材料，详细信息支持子智能体深入核验，原件和解析内容可按需回查。合同、验收材料、证书等围绕同一事实组织，减少重复阅读；资料复用限于授权范围，并重新检查时效与本次要求。

**多智能体按问题分工。** 规则整理、资料入库、主审核与资料核验各司其职。每份投标文件可配置不同规则库和资料库，先判断项目适用性，再逐项审核；需要证明的事项交给子智能体读取指定材料。正文、表格和图片通过通用工具参与核验，避免把整库无差别塞入每次审核。长材料按连续完整结构分批，结合上下文管理保持任务衔接。

**结论形成与交付同源。** 审核冻结所选规则、资料及解析版本，实际读取的来源进入台账，已登记且被引用的内容可呈现为报告依据。主智能体维护报告草稿，程序检查规则覆盖、结构和来源，生成统一结果供网页、Markdown、Word和JSON使用。流程图、智能体调用图、轨迹树及历史回放使用户看清处理阶段与关键调用，报告区分事实、判断和复核建议。

| 应用场景 | 共用审核任务 | 项目化配置示例 |
| --- | --- | --- |
| 货物采购 | 参数响应、资格与供货证明核对 | 型号、性能阈值、交付条件、检测资料 |
| 工程招标 | 资格、业绩、人员与技术响应核对 | 专业要求、人员条件、合同及验收材料 |
| 服务采购 | 服务范围、人员配置与履约能力核对 | 服务等级、周期、团队要求、业绩证明 |

上述场景共享架构，具体效果按样本独立验证。电力采购用于首批验证，不限定产品行业。对工程量清单计价、专业评分或外部真实性认证等专门能力，按需求另行评估工具与规则，不能以通用文档理解代替专业验证。

交付设置两种形态：独立工作台供业务团队完成材料管理、审核与复核；嵌入式模块面向已有采购系统，拟通过接口对接文件、任务和报告。两者共用引擎，客户按现有系统与部署环境选择，形成从试点到正式接入的连续路径。

使用路径从规则审阅开始：业务人员确认本项目审核要求，整理相关证明材料，为待审文件选择对应双库，再查看报告重点与逐项依据。规则库承担“按什么审”，资料库承担“用什么证明”，审核任务承担“本次具体判断”，三者相互衔接又保留独立管理边界。项目变化时更新适用规则，资料变化时重新核对事实，已形成报告保持当时依据。

产品服务还包括导入规范、规则整理指导、复核培训和问题支持，使新用户能理解结论与材料之间的关系。不同岗位可借助同一报告沟通疑点，减少重复摘录与口头转述；所减少的实际工作量通过试点评测量化。

### 2.产品（服务）化实施计划

拟以“样本验证—受控试点—标准交付”推进，阶段以验收成果衔接。首先建立覆盖货物、工程、服务的授权样本，分别标注规则、结论与支持证据，测量漏检、误报、引用支持率、完整产出率和复核工时；优先验证资格、响应与一致性等共同任务，再增加行业专门规则。各类样本规模及指标门槛为【待填】，不以单一场景结果代替跨场景验收。

其次与意向使用方开展并行试点，在原人工流程之外运行系统，由业务人员对照复核；保存全部成功与失败记录，形成问题清单、成本报告和适用范围。试点同时核查文件格式、扫描质量、规则冲突和长材料处理，区分模型判断问题、解析问题与执行故障。达到约定标准后再进入实际辅助流程。

随后形成版本包、接口说明、部署脚本、培训教材和运行手册，开展升级回归、备份恢复和交付验收。当前原型为单进程任务且无用户鉴权；企业交付前须补齐认证授权、访问审计、数据保留、任务调度与故障恢复。云模型调用按客户授权控制出域范围；内网方案须完成模型适配与端到端验收。以标准核心、可配置项目规则和受控版本升级降低后续交付成本。

## 四、项目产品（服务）市场与竞争（不超过2000字）

### 1.市场概述

招投标审核需求横跨货物、工程和服务，其共同工作是依据项目要求阅读材料、查找响应、核对证明并留存判断依据。财政部公布的2025年政府采购结构中，三类占比分别为23.95%、39.28%、36.77%，公开招标占77.49%，说明需求具有跨品类基础。该统计仅反映政府采购，不等于全部招采市场，更不能直接折算软件收入。[财政部数据](https://www.ccgp.gov.cn/news/202609/t20260928_27408954.htm)

2026年有关实施意见提出推广投标合规自查、智能辅助评标等场景，强调系统集成、数据治理与人的自主判断。本项目以材料审核和复核服务承接相关需求，商业路径同时考虑独立使用与嵌入既有平台。[政策依据](https://www.ndrc.gov.cn/xwdt/tzgg/202602/t20260210_1403681_ext.html)

| 客户群 | 使用者与购买决策方 | 购买触发与支付理由 |
| --- | --- | --- |
| 采购单位、企业采购中心 | 审核人员使用；采购管理与信息化部门共同评估 | 项目增多、材料复杂、跨部门复核，购买更稳定的核查与依据整理能力 |
| 招标代理及专业咨询机构 | 项目经理、审核人员使用；业务负责人决策 | 多项目并行、交付口径不一致，购买可复用规则与标准报告能力 |
| 交易平台及系统服务商 | 平台业务部门提出需求；产品和技术部门评估接入 | 已有流程需要智能审核模块，购买接口集成、版本维护与服务保障 |

市场进入优先选择采购频次稳定、样本可授权、负责人明确的单位，不仅按行业划分。按客户群测算新增潜客N、新客转化率a、老客户续费率r及客均当年确认服务收入P，再汇总收入；各值为【待测算】，渠道客户与终端客户去重。首期目标是验证真实付费与续费条件，形成可复制场景和交付方式。

客户筛选同时考虑材料复杂度、重复审核量与现有系统接口条件。优先进入问题明确、改造范围可控的业务环节，以采购周期和预算安排规划销售，避免将有需求但缺预算的访谈对象计入近期收入。

### 2.竞争优势分析

市场已出现不同层次的成熟产品。新点智慧招采覆盖交易及辅助评标，包含初步、商务、技术评审和参考报告；广联达清标围绕工程清单开展符合性、计算性、报价分析和技术标检查；SAP的新一代Ariba将投标分析智能体放入企业采购流程，相关能力分阶段交付。[新点](https://www.epoint.com.cn/eweb/cpyfw/042002/042002002/?kind=ggzyjy)、[广联达](https://m-pre.glodon.com/product/314.html)、[SAP](https://news.sap.com/2026/03/next-gen-sap-ariba-foundation-for-intelligent-procurement/)

标智通的竞争着力点是通用材料审核的产品组合：规则从项目材料产生，使同一内核适应不同要求；资料独立组织，支撑证明可按任务复用；主子智能体围绕具体规则委派核验；冻结版本、读取台账和同源报告共同支持复核。独立工作台适应直接使用，嵌入模块适应既有系统增量建设。与成熟平台比较时，重点验证适配周期、审核质量、复核工时及总交付成本，不以功能名称宣称排他优势。

可持续积累来自授权样本的评测方法、解析与核验错误分类、项目配置规范、接口适配和交付经验。客户专有规则与材料按约定隔离，跨客户复用软件组件及获授权的通用经验，不靠汇集客户原件形成壁垒。随着更多场景验证，逐步形成可版本管理的规则组织范式与回归案例，提升新项目适配和维护效率。

### 3.项目实施风险及应对措施

| 主要风险 | 应对措施 |
| --- | --- |
| 跨场景适配不足 | 按任务类型与材料难度分层验证，保留行业术语、阈值及例外；超出能力的事项交专业复核 |
| 漏检、误报或报告未完成 | 分别验收判断质量与完整产出；纳入失败样本，设置人工复核和版本回归，不用格式通过代替业务正确 |
| 数据授权与模型依赖 | 明确材料权属、允许调用范围及删除要求；对模型更新开展回归，按环境验证云端或内网方案 |
| 长销售周期、定制成本失控 | 以付费试点和明确验收推动转化，限定免费适配范围；将共性需求产品化、特殊需求单独报价 |
| 对结果过度依赖 | 展示依据和不确定性，明确使用责任；将真实性认证、专业评分与辅助材料审核区分 |

## 五、商业模式（不超过2000字）

### 1.项目产品（服务）的开发、生产（服务）策略

拟采用“通用核心研发、项目规则配置、客户环境交付”的服务模式。核心版本统一维护解析、检索、智能体协同、来源管理和报告能力；项目配置围绕招标要求、资料组织和报告习惯展开；部署层适配客户模型、存储与业务系统。共性需求进入标准版本，个别客户的专属功能明确开发范围与费用，避免多个互不兼容的定制分支。

交付从需求和授权清单开始，依次完成样本验证、试点部署、使用培训、联合验收与维护。验收明确可处理材料、指标口径、报告范围、故障处置及人工复核职责。服务中收集经允许的错误类型和使用反馈，形成回归用例；不将客户保密原件默认纳入共享训练或公共样本库。

首期研发预算优先投入跨场景样本与业务评测、解析稳定性、企业部署能力及接口标准化。配置和样本变化需记录版本，软件升级先验证再发布。模型调用与交付人力分别记录成本，以任务完整产出和复核工作量评估改进价值，避免仅追求更多调用或更复杂架构。

### 2.项目产品（服务）的营销策略

采用“真实样本演示—有边界的付费试点—年度服务—扩展部署”的转化路径。演示展示一项判断如何对应规则、响应与证明，试点选择多份有差异的材料，与原人工流程比较，明确验收、费用和产物归属。业务人员重点看结论与依据，管理者看复核工时及质量，信息化人员看接入、安全和维护成本，各方共同形成购买依据。

直达客户优先拓展采购单位与代理机构，围绕稳定项目量和重复核查任务建立样板；渠道合作面向采购系统服务商，以模块接入、联合交付和持续维护创造收益。伙伴可通过接口适配、部署及客户支持获得约定服务收益，项目团队负责核心版本与问题响应，分工和收费写入合同，不预设已有伙伴。

续费依据包括有效使用项目数、人工复核时间、经复核的问题发现、系统稳定性和服务响应。定期回顾低使用量原因，区分材料不足、操作障碍和效果不达预期；通过培训、配置优化和版本改进提高留存。扩展到新部门或新场景须重新核对授权和适配效果，不将试点意向或免费使用计为付费客户。

### 3.项目产品（服务）获利方式

拟采用年度标准服务、模块许可与实施适配相结合的收费结构。年度服务按部署范围和约定用量覆盖软件使用、基础维护及模型额度；模块许可面向平台集成，明确接口、部署范围和维护责任。单次试点与专项适配按约定工作量和验收成果计费，转为年度服务时按合同处理已付费用，避免同项重复收费。

| 收费项目 | 交付及计价基础 | 拟价格 |
| --- | --- | --- |
| 独立工作台年度服务 | 单位、部署范围、年度审核额度 | 【待测算】万元/家·年 |
| 嵌入模块年度许可 | 部署实例、接口范围与约定调用额度 | 【待测算】万元/套·年 |
| 试点、部署与专项适配 | 样本规模、对接工作量及验收成果 | 【待测算】万元/项目 |

用量拟按约定的有效审核任务计量，并对页数、材料规模或模型费用设置透明额度；失败重试和超额使用的计费在合同中说明。价格经成本与付费意愿验证，不与中标、否决数量或采购金额挂钩。

单位经济性按完整服务年计算，以标准年度服务价格p减去客均年度直接成本c得到贡献额，c含模型使用、专属运维及渠道履约成本。固定研发、销售和管理费用为F，在无一次性实施净贡献的简化条件下，盈亏平衡付费单位数为F÷(p−c)，仅在p大于c时有意义。实际经营另核算实施项目收入与成本、账期及现金流；对转化率、续费率、单任务模型成本和定制工时分别做敏感性分析。

经营管理按客户记录获客投入、交付工时、支持工时和年度贡献。若定制投入持续超过可回收服务收入，则调整范围、重新报价或暂缓扩展；标准模块复用带来的成本下降通过实际交付记录验证。

### 4.（若创业）企业发展计划
