# 任务 01：工程骨架与配置基线

## 1. 目标

一次性建立后续任务所需的完整 Python 工程骨架，让开发开始时可以直接看到整个项目的模块边界、文件位置和实现顺序；同时完成应用入口、配置加载、日志规范和测试入口。

该任务必须创建后续任务预计使用的代码文件，但不提前实现审核业务。除任务 01 自身负责的基础模块外，其余 Python 文件只写一行模块注释说明用途。

当前项目环境已经通过 uv 初始化：

```text
Python 3.11
.python-version
pyproject.toml
uv.lock
.venv
```

任务实施时直接使用现有环境，不重新初始化项目，也不删除或重建 `uv.lock`。

### 1.1 项目总览

任务 01 首先要在根目录 `README.md` 中给出项目总览，再创建代码骨架。总览至少回答以下问题：

1. 系统解决什么问题。
2. 三类输入数据分别是什么。
3. 从上传文件到生成报告的主流程是什么。
4. 哪些步骤是普通确定性程序，哪些步骤调用 LLM，哪些步骤进入 LangGraph。
5. 各代码目录分别承担什么职责。
6. 当前开发任务的实施顺序是什么。

系统主链路：

```text
招标文件夹
  -> 文档解析
  -> LLM 抽取 RuleSet
  -> 招标依据索引

投标方资料文件夹
  -> 文档解析
  -> LLM 资料分类
  -> Evidence Index

投标文件测试集
  -> 文档解析
  -> Bid Document Index
  -> bid_agent 按 RuleSet 逐项审核
  -> evidence_subagent 按 Claim 核验资料
  -> AuditResult
  -> JSON
  -> Word
```

运行边界：

```text
LangGraph 之前
  文件上传、文件存储、文档解析、规则抽取、资料分类、Embedding、索引构建

LangGraph 内部
  bid_agent ReAct
    -> 投标响应检索
    -> 规则原文回查
    -> request_evidence_review
       -> evidence_subagent ReAct

LangGraph 之后
  AuditResult Schema 校验、JSON 落盘、Word 模板渲染
```

模块总览：

| 模块 | 作用 |
|---|---|
| `api` | 接收项目、投标方资料和测试集上传，查询任务状态 |
| `services` | 编排普通业务流程和后台任务 |
| `storage` | 管理 SQLite 元数据和本地文件 |
| `parsers` | 将 DOCX、XLSX、TXT 转为统一解析结果 |
| `models` | 定义所有共享 Schema 和 Agent 契约 |
| `llm` | 适配 Chat、Embedding 和进程内 Rerank 模型 |
| `retrieval` | 建立本地索引并完成过滤、召回和排序 |
| `rules` | 抽取、合并和确定性评估审核规则 |
| `evidence` | 分类投标方资料 |
| `tools` | 为主/子 Agent 提供受控检索工具 |
| `agents`、`graph` | 实现主审核 Agent、资料核验子 Agent 和状态流转 |
| `reports` | 将 AuditResult 写为 JSON 并渲染 Word |

开发顺序：

```text
工程总览与骨架
  -> 领域模型
  -> SQLite 与文件存储
  -> 文档解析
  -> 模型适配
  -> 本地检索
  -> 项目规则预处理
  -> 投标方资料预处理
  -> 审核任务生命周期
  -> Agent 工具
  -> 资料核验子智能体
  -> 主审核智能体
  -> JSON/Word 输出
  -> 全链路验收
```

根目录 `README.md` 在任务 01 完成时至少包含：

- 上述系统主链路和边界。

## 3. 核心约束

- Python 版本以当前 `.python-version` 中的 3.11 为开发基线。
- 使用 uv 管理依赖和虚拟环境，新增依赖通过 `uv add` 写入 `pyproject.toml` 和 `uv.lock`。
- `uv.lock` 必须提交到 Git；`.venv` 和 uv 本地缓存不得提交。
- 模型 YAML 中写 URL、API Key 的环境变量占位符，真实值放在根目录 `.env`，不得提交到 Git。
- 提交不含真实凭据的 `.env.example`，用于说明必需变量。
- 模型名、温度、超时、最大输出 token、重试次数和批大小等非敏感参数放在 `configs/model.yaml`。
- 更换某类模型时优先直接修改该职责对应的 YAML 节点；不要求修改 Python 文件。
- 模型地址、模型名、Key、温度、超时和批大小不得写死在业务代码。
- 数据目录必须可通过配置切换，数据库内只保存相对路径。
- 配置读取与当前工作目录解耦，使用项目根目录或显式环境变量定位。
- 不在模块导入时连接模型服务、创建数据库或加载大模型。
- 任务 01 完成后，后续任务所需 Python 文件必须已经存在，后续开发主要是在既定文件中补充实现。
- 所有 Python 文件必须有一行模块级中文 docstring。
- 不使用 `.gitkeep`；运行时目录和生成物目录按需创建。

```yaml
    passages by how directly and completely they provide evidence for the
    requirement.
  local_files_only: false
  allow_degradation: true
```

真实 `.env` 由开发者本地维护。配置加载规则固定为：

```text

  -> .env / 进程环境变量替换 ${VAR_NAME}
  -> Pydantic 校验最终配置
```

同名变量同时存在于 `.env` 和进程环境变量时，进程环境变量优先。

### 5.6 Prompt 统一加载

Prompt 正文统一使用 Markdown，不为每套 Prompt 创建 Python 文件。Prompt 和 Tool 说明集中放在根目录 `configs/prompts/`，模型与检索等 YAML 配置仍各自独立。

`app/prompts/loader.py`：

```python
from functools import lru_cache
from string import Template

from app.core.config import PROJECT_ROOT

PROMPT_ROOT = PROJECT_ROOT / "configs" / "prompts" / "templates"
TOOL_DESCRIPTION_PATH = (
    PROJECT_ROOT / "configs" / "prompts" / "tool_descriptions.yaml"
)


@lru_cache
def load_prompt(name: str) -> str:
    """读取并缓存指定 Markdown Prompt。"""
    path = PROMPT_ROOT / f"{name}.md"
    if not path.is_file():
        raise FileNotFoundError(f"Prompt 不存在: {name}")
    return path.read_text(encoding="utf-8")


def render_prompt(name: str, **variables: object) -> str:
    """使用 $variable 语法渲染 Prompt，并检查缺失变量。"""
    template = Template(load_prompt(name))
    return template.substitute(
        {key: serialize_prompt_value(value) for key, value in variables.items()}
    )


@lru_cache
def load_tool_description(name: str) -> str:
    """读取指定 BaseTool 的模型可见说明。"""
    definitions = yaml.safe_load(
        TOOL_DESCRIPTION_PATH.read_text(encoding="utf-8")
    )
    item = definitions["tools"].get(name)
    if item is None:
        raise KeyError(f"Tool description 不存在: {name}")
    return item["description"].strip()
```

调用方式：

```python
system_prompt = load_prompt("bid_agent")

rendered_prompt = render_prompt(
    "rule_extraction",
    source_context=source_context,
    output_schema=RuleExtractionBatch.model_json_schema(),
)

tool_description = load_tool_description("search_bid_response")
```

`configs/prompts/tool_descriptions.yaml`：

```yaml
tools:
  search_bid_response:
    description: |
      根据当前 RuleItem 在指定投标文件中检索响应片段。
      仅用于定位投标响应，不用于查询投标方证明材料。

  retrieve_rule_source:
    description: |
      当结构化规则存在歧义或需要补充引用时，
      回查当前项目的招标规则原文。

  request_evidence_review:
    description: |
      当投标响应中的声明需要合同、证书或参数表等材料证明时调用。
      每次只提交一条 Claim。

  search_evidence:
    description: |
      按 Claim 和 required_evidence_types 检索当前投标方资料。
      返回候选材料，不直接形成支持结论。

  retrieve_evidence_source:
    description: |
      对证据候选回查完整原文、表格、解析状态和来源位置。
```

约束：

- Prompt 文件只保存文本指令、静态示例和 `$variable` 占位符。
- Tool 的模型可见说明只保存在 `tool_descriptions.yaml`，Tool 类通过名称加载。
- 当前业务对象如何筛选、截断和序列化，由 extractor/classifier/agent 模块负责。
- Pydantic Schema 是结构化输出的事实来源，Prompt 可以注入其导出结果，但不单独维护第二份 Schema。
- 修改 Prompt 文本不需要修改 Python 代码。

## 6. 测试设计

- 根目录 README 包含项目定位、主链路、运行边界、目录结构和启动命令。
- 完整工程结构中的 Python 代码文件均已创建。
- 所有 `app/**/*.py` 都有一行模块级中文 docstring。
- 仓库中不存在用于占空目录的 `.gitkeep`。
- 执行模块导入烟雾测试时，不连接数据库或模型服务，也不读取业务数据。
- 三个 API 模块均能导出空 `APIRouter`，供 `app/main.py` 安全注册。
- 四个 Markdown Prompt 可通过统一 loader 读取。
- 五个 Tool description 可通过统一 loader 读取，缺失项启动测试失败。
- Prompt 缺失或模板变量缺失时给出明确错误。
- 配置文件不存在时给出明确错误，不静默使用危险默认值。
- `.env` 可以提供模型 API Key、Base URL 和 LangSmith 配置。
- 进程环境变量优先于 `.env`；YAML 中的 URL/Key 占位符能正确替换。
- 修改 YAML 中的模型名、温度和超时后无需修改 Python。
- 四类 LLM 调用能读取各自的温度配置。
- 日志和错误响应不得输出 API Key。
- 从任意工作目录启动时均能定位配置。
- 应用启动不会尝试连接不存在的模型服务。
- 数据目录创建失败时应用启动失败并记录原因。
- `uv run uvicorn app.main:app --reload` 可以启动应用。
- 修改 `app` 下的 Python 文件后，开发服务能够自动重载。
- `/health` 返回 HTTP 200 和固定结构。

## 7. 验收标准

- 打开根目录 README 即可理解系统目标、数据流、LangGraph 边界和开发顺序。
- 可以从目录树直接定位后续每个 task 的代码文件。
- 所有后续 Python 模块文件已创建，并通过一行注释说明用途和实现任务。
- 所有 Python package 均包含 `__init__.py`，全部模块可安全导入。
- Agent Prompt 保存在 `configs/prompts/templates/*.md`，Tool 说明保存在 `configs/prompts/tool_descriptions.yaml`，Python 侧只有统一 `loader.py`。
- 使用 `uv run uvicorn app.main:app --reload` 可以启动开发服务。
- 健康检查接口返回应用版本和基本状态。
- 配置由统一入口读取，业务模块不直接解析 YAML。
- `.env.example` 包含所需变量但不含真实凭据，真实 `.env` 已被 Git 忽略。
- 模型 URL、Key、模型名、温度、超时和批大小均可配置。
- 日志中包含时间、级别、模块、`project_id/bidder_id/task_id` 可选上下文字段。
- `pytest` 有可运行的最小测试入口。
- `pyproject.toml`、`.python-version` 和 `uv.lock` 的 Python 版本约束一致。
