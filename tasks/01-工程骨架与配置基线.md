# 任务 01：工程骨架与配置基线

## 1. 目标

建立后续模块共同依赖的 Python 工程骨架、应用入口、配置加载方式、日志规范和测试入口。该任务不实现审核业务。

## 2. 范围

建议创建：

```text
app/
configs/
tests/
data/.gitkeep
pyproject.toml
```

核心模块：

- `app/main.py`：FastAPI 应用入口和生命周期。
- `app/core/config.py`：配置模型与加载。
- `app/core/logging.py`：统一日志初始化。
- `app/core/errors.py`：业务异常与 API 错误响应。
- `configs/model.yaml`、`retrieval.yaml`、`storage.yaml`。

## 3. 核心约束

- Python 版本固定为项目实际部署环境支持的单一版本，建议先以 3.10 为基线。
- 模型地址、模型名、Key、超时、批大小不得写死在业务代码。
- 数据目录必须可通过配置切换，数据库内只保存相对路径。
- 配置读取与当前工作目录解耦，使用项目根目录或显式环境变量定位。
- 不在模块导入时连接模型服务、创建数据库或加载大模型。

## 4. 核心伪代码

### 4.1 配置模型

```python
class AppSettings(BaseSettings):
    # 基础运行配置
    app_name: str
    debug: bool = False
    data_root: Path

    # 按职责拆分，禁止业务代码自行读取 YAML
    chat_model: ChatModelSettings
    embedding_model: EmbeddingSettings
    rerank_model: RerankSettings
    retrieval: RetrievalSettings
    storage: StorageSettings


@lru_cache
def get_settings() -> AppSettings:
    project_root = locate_project_root()

    # YAML 提供默认值，环境变量覆盖敏感项和部署差异。
    raw = merge_yaml_files(
        project_root / "configs/model.yaml",
        project_root / "configs/retrieval.yaml",
        project_root / "configs/storage.yaml",
    )
    raw = override_from_environment(raw)
    return AppSettings.model_validate(raw)
```

### 4.2 应用生命周期

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    settings = get_settings()

    # 启动检查只验证必要目录和数据库结构。
    # 不在这里预加载全部模型或执行耗时索引任务。
    ensure_data_directories(settings.data_root)
    initialize_database()
    mark_interrupted_tasks_failed()

    yield

    # 关闭共享 HTTP Client 等轻量资源。
    await close_model_clients()


app = FastAPI(lifespan=lifespan)
app.include_router(project_router)
app.include_router(bidder_router)
app.include_router(audit_task_router)
```

### 4.3 统一错误响应

```python
class BusinessError(Exception):
    code: str
    message: str
    http_status: int
    details: dict | None


@app.exception_handler(BusinessError)
async def handle_business_error(request, exc):
    return JSONResponse(
        status_code=exc.http_status,
        content={
            "error": {
                "code": exc.code,
                "message": exc.message,
                "details": exc.details,
            }
        },
    )
```

## 5. 测试设计

- 配置文件不存在时给出明确错误，不静默使用危险默认值。
- 环境变量可以覆盖模型 API Key、Base URL 和数据目录。
- 从任意工作目录启动时均能定位配置。
- 应用启动不会尝试连接不存在的模型服务。
- 数据目录创建失败时应用启动失败并记录原因。

## 6. 验收标准

- `app` 可以启动，健康检查接口返回应用版本和基本状态。
- 配置由统一入口读取，业务模块不直接解析 YAML。
- 日志中包含时间、级别、模块、`project_id/bidder_id/task_id` 可选上下文字段。
- `pytest` 有可运行的最小测试入口。

## 7. 非目标

- 不实现数据库业务表。
- 不实现上传、解析、索引和 Agent。
- 不引入 Redis、Celery、Elasticsearch 或 PostgreSQL。
