# 任务 08：投标方资料入库与分类

## 1. 目标

实现投标方资料上传接口：创建 Bidder、解析资料、使用 LLM 分类、构建带证据类型元数据的 Evidence Index，并将投标方状态设置为 `evidence_ready`。

## 2. 建议文件

```text
app/api/bidders.py
app/services/bidder_service.py
app/evidence/classifier.py
app/prompts/evidence_classification.py
```

## 3. API

```http
POST /api/projects/{project_id}/bidders
Content-Type: multipart/form-data
```

成功返回：

```json
{
  "project_id": "project-001",
  "bidder_id": "bidder-001",
  "status": "evidence_ready"
}
```

## 4. 核心约束

- 一次上传只对应一家投标方。
- 目录名只作为分类参考，不能直接决定证据类型。
- 分类标签统一使用 `EvidenceType`。
- 低置信度或无法分类时：`evidence_type=other` 且 `classification_status=manual_review`。
- 所有证据索引必须同时绑定 `project_id` 和 `bidder_id`。

## 5. 核心伪代码

### 5.1 资料入库流程

```python
async def create_bidder(project_id, files, relative_paths):
    project = require_project(project_id)
    bidder = bidder_repository.create(
        project_id=project.project_id,
        status="processing_evidence",
    )

    try:
        documents = file_store.save_many(
            owner=BidderOwner(project_id, bidder.bidder_id),
            data_role="evidence_material",
            files=files,
            relative_paths=relative_paths,
        )

        classified_documents = []
        for document in documents:
            parsed = parse_document(document)
            classification = await classify_evidence_document(
                document,
                parsed,
            )
            classified_documents.append(
                attach_classification(document, classification)
            )

        await build_document_index(
            index_scope=EvidenceScope(project_id, bidder.bidder_id),
            documents=classified_documents,
        )

        bidder_repository.mark_evidence_ready(bidder.bidder_id)
        return bidder_repository.get(bidder.bidder_id)

    except Exception as exc:
        bidder_repository.mark_evidence_failed(bidder.bidder_id, exc)
        raise
```

### 5.3 分类调用和降级

```python
async def classify_evidence_document(document, parsed):
    if parsed.parse_status in {"unsupported", "ocr_required"}:
        return EvidenceClassification(
            evidence_type="other",
            confidence=0,
            classification_status="manual_review",
            reason="当前解析结果不足以自动分类",
        )

    result = await chat_model.complete_structured(
        messages=evidence_classification_prompt(
            one_shot=CLASSIFICATION_EXAMPLE,
            input=build_classification_input(document, parsed),
        ),
        output_model=EvidenceClassification,
    )

    if result.confidence < settings.classification_threshold:
        return result.model_copy(
            update={
                "evidence_type": "other",
                "classification_status": "manual_review",
            }
        )
    return result
```

## 7. 测试设计

- “业绩文件”目录中的合同、发票和业绩表可分类为不同类型。
- 修改目录名不应改变明显文件内容的分类结论。
- 图片型证书进入人工复核，不按文件名直接判定有效。
- 相同证据类型在不同 bidder 下严格隔离。
- 分类成功但索引失败时 bidder 不得标记为 `evidence_ready`。
- 项目不存在时不能创建 bidder。

## 8. 验收标准

- 每个资料文件都有分类结果和解析状态。
- Evidence Index 可按证据类型过滤。
- `evidence_ready` 仅在全部必要处理完成后设置。
- 分类 Prompt、索引和 Claim 使用同一 EvidenceType 枚举。
