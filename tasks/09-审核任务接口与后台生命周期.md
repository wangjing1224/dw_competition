# 任务 09：审核任务接口与后台生命周期

## 1. 目标

实现测试集上传、审核任务创建、Bid Document Index 构建、进程内后台执行和任务查询接口。该任务先建立生命周期和调用边界，不实现主审核图内部逻辑。

## 2. 建议文件

```text
app/api/audit_tasks.py
app/services/audit_task_service.py
app/services/background_runner.py
```

## 3. API

### 创建任务

```http
POST /api/projects/{project_id}/bidders/{bidder_id}/audit-tasks
```

先返回：

```json
{
  "task_id": "audit-001",
  "status": "running"
}
```

### 查询任务

```http
GET /api/audit-tasks/{task_id}
```

返回运行状态、进度；完成后返回结果和输出路径。

## 4. 核心约束

- Project 必须为 `rule_ready`。
- Bidder 必须属于 Project 且为 `evidence_ready`。
- 只有该接口进入 LangGraph。
- 每次上传创建新的 task_id，不复用历史任务。
- 后台任务使用自己的数据库连接。
- 当前版本应用重启不自动恢复运行中任务。

## 5. 核心伪代码

### 5.1 创建任务

```python
async def create_audit_task(project_id, bidder_id, files, relative_paths):
    project = require_project_status(project_id, "rule_ready")
    bidder = require_bidder(project_id, bidder_id, status="evidence_ready")

    task = task_repository.create(
        project_id=project.project_id,
        bidder_id=bidder.bidder_id,
        status="running",
        progress={"stage": "saving_files", "completed": 0, "total": len(files)},
    )

    try:
        documents = file_store.save_many(
            owner=TaskOwner(project_id, bidder_id, task.task_id),
            data_role="bid_document",
            files=files,
            relative_paths=relative_paths,
        )
    except Exception as exc:
        task_repository.mark_failed(task.task_id, exc)
        raise

    # 返回前只保证任务和原始文件已持久化。
    background_runner.submit(
        run_audit_task,
        task_id=task.task_id,
        document_ids=[doc.file_id for doc in documents],
    )
    return task
```

### 5.2 后台流程骨架

```python
def run_audit_task(task_id, document_ids):
    with new_execution_context(task_id):
        try:
            update_progress(task_id, stage="parsing_bid_documents")
            documents = load_task_documents(task_id, document_ids)
            parsed = [parse_document(doc) for doc in documents]

            update_progress(task_id, stage="building_bid_index")
            run_async(
                build_document_index(
                    index_scope=BidScope(task_id),
                    documents=documents,
                )
            )

            update_progress(task_id, stage="auditing")
            audit_result = run_audit_graph(build_audit_context(task_id))

            update_progress(task_id, stage="writing_outputs")
            finalize_outputs(task_id, audit_result)

        except Exception as exc:
            task_repository.mark_failed(
                task_id,
                error=to_task_error(exc),
            )
```

### 5.4 查询接口

```python
def get_audit_task(task_id):
    task = task_repository.get(task_id)

    response = {
        "task_id": task.task_id,
        "status": task.status,
        "progress": task.progress,
    }
    if task.status in COMPLETED_STATUSES:
        response["result"] = read_json_if_available(task.json_path)
        response["outputs"] = {
            "json": task.json_path,
            "word": task.word_paths,
        }
    if task.status == "failed":
        response["error"] = task.error
    return response
```

## 7. 测试设计

- `rule_failed` 项目不能创建 task。
- bidder 不属于 project 时返回明确错误。
- bidder 索引未完成时不能创建 task。
- 创建两个 task 时拥有独立 Bid Index 和输出目录。
- 后台失败后查询接口返回 `failed` 和结构化错误。
- 应用重启后遗留任务被任务 03 的恢复逻辑标记失败。

## 8. 验收标准

- 创建接口快速返回 task_id。
- 后台流程的每个阶段可更新进度。
- 查询接口覆盖设计中的四种状态。
- LangGraph 前后的业务流程边界明确，不把上传和报告渲染放进图内。
