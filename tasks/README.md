# 电力智能招标审核系统开发任务总览

## 1. 使用说明

本目录依据 `documents/电力智能招标审核系统设计文档.md` 拆分开发任务。本轮文档只描述实施边界、核心接口和伪代码，不包含可直接运行的全量业务代码。

开发时遵循以下原则：

- 以设计文档为唯一架构依据；任务文档用于安排实施顺序，不替代设计文档。
- 当前主工程使用 uv 管理 Python 3.11 环境，`uv.lock` 作为依赖锁文件提交。
- 开发后端统一使用 `uv run uvicorn app.main:app --reload` 启动。
- 每个任务的伪代码必须通过“文件职责与伪代码归属”表绑定到具体文件；实施时不得只按目录猜测落点。
- 每个任务完成后先执行该任务的单元测试和验收项，再进入依赖它的任务。
- JSON Schema、Pydantic 模型、状态枚举和 ID 归属一旦进入后续任务，不随意改名。
- `project_id + bidder_id + task_id` 必须贯穿上传、索引、检索、Agent State 和输出。
- LLM 不直接写文件、不直接修改 State、不决定任务是否完成。
- JSON 是审核结果的唯一事实来源，Word 只负责展示。

## 2. 素材代码复用边界

素材目录：`material/lib-zlf`

可复用或改造：

- `zlfkblib/parse/parsers/docx_parser.py`：DOCX 段落、图片状态、表格转写思路。
- `zlfkblib/parse/parsers/txt_parser.py`：TXT 编码识别和基础切分思路。
- `zlfkblib/parse/chunk.py`：解析片段模型的基础形式。
- `zlfkblib/utils/rag_tokenizer.py`：中文切分辅助能力，需隔离为可替换实现。

不得直接沿用：

- Elasticsearch 存储与检索：设计要求本地轻量索引和 NumPy 相似度。
- `zlfkblib.retrieve.retrieve` 的全局单索引：缺少项目、投标方、任务强制隔离。
- `zlfkblib.llm` 对 Ollama 私有客户端的直接依赖：设计要求 OpenAI 兼容协议适配层。
- `zlfkblib.embedding` 在业务进程内直接加载 BGE：设计要求通过可配置 Embedding Adapter 调用本地服务。
- `main.py` 的问答式流程：与规则驱动审核、LangGraph State 和最终 Schema 不同。

建议实施方式：提取所需算法和解析逻辑到主工程模块，补齐统一模型、来源定位、解析状态和测试；不要把素材库整体作为业务核心依赖。

## 4. 推荐里程碑

### M1：数据基础可用

完成任务 01～06。此时应能上传文件、解析、建立带强制元数据隔离的本地索引，并独立验证检索质量。

### M2：预处理闭环可用

完成任务 07～09。此时应能创建项目、投标方和审核任务，生成固定 RuleSet、Evidence Index 和 Bid Document Index。

### M3：智能审核闭环可用

完成任务 10～13。此时应能运行主/子 ReAct、生成完整 AuditResult、写入 JSON 并渲染 Word。

### M4：比赛数据验收

完成任务 14。两份红外热成像仪投标文件进入审核，机械加工设备文件被排除，全部结论可追溯。

### M5：性能与审核流程重构

完成任务 15。规则只设置最多 30 条的总量上限，投标文件先完成详细摘要和相关性路由，相关文件按全部规则一次进入主 Agent，资料子 Agent 按需短循环核验，JSON 与 Word 完整一致。

### M6：真实数据质量与上下文收敛

完成任务 16。规则先经过审核阶段准入和全局归并，再形成不超过 30 条的有效审核点；主 Agent 使用 Markdown 主结构、轻量规则和去重片段，输出分类总结与规则简短结论，完整业务 JSON 由代码确定性拼接。

## 5. 全局完成定义

- 所有 API 使用统一错误结构和状态枚举。
- 所有索引检索先执行元数据过滤，再执行召回和排序。
- 所有适用规则均产生 `Finding`，未找到响应也不能跳过。
- 需要证据的已响应规则具有 `EvidenceReviewResult` 或明确人工复核原因。
- 机械加工设备异类文件不调用资料核验。
- 任务级 JSON 先通过 Schema 校验并落盘，之后才生成 Word。
- Word 失败时保留 JSON，并将任务状态设为 `completed_with_report_error`。
- 测试覆盖跨项目、跨投标方和跨任务数据不得串用。
- Embedding 模型或维度变化后，当前开发阶段删除 `data/indexes/` 和 `data/app.db`，再重新调用项目、投标方和审核任务接口完成全量重建，不额外设计重建 API。
