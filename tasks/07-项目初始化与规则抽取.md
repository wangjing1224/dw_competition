# 任务 07：项目初始化与规则抽取

## 1. 目标

实现招标文件上传接口和项目初始化流程：安全保存文件、解析规则源、调用 LLM 抽取规则、去重合并、处理冲突、生成固定 RuleSet，并构建招标依据索引。

## 3. API

```http
POST /api/projects
Content-Type: multipart/form-data
```

成功返回：

```json
{
  "project_id": "project-001",
  "status": "rule_ready"
}
```

第一版可同步完成项目初始化；若实际规则抽取耗时过长，可在不改变业务模型的前提下改为后台处理，但测试集审核必须等待 `rule_ready`。

## 4. 核心流程

```text
创建 Project
  -> 保存招标文件
  -> 逐文件解析
  -> 构建招标依据索引
  -> 按文件/章节调用规则抽取
  -> 规则规范化、去重和冲突处理
  -> 生成并校验 RuleSet
  -> 原子写入 RuleSet JSON
  -> Project = rule_ready
```

### 5.1 项目服务

```python
async def create_project(files, relative_paths):
    project = project_repository.create(status="processing_rules")

    try:
        documents = file_store.save_many(
            owner=ProjectOwner(project.project_id),
            data_role="rule_source",
            files=files,
            relative_paths=relative_paths,
        )

        parsed_documents = [
            parse_document(document)
            for document in documents
        ]
        ensure_rule_sources_usable(parsed_documents)

        await build_document_index(
            index_scope=RuleSourceScope(project.project_id),
            documents=documents,
        )

        rule_set = await extract_and_merge_rule_set(
            project.project_id,
            parsed_documents,
        )
        validate_rule_set(rule_set)
        rule_path = write_rule_set_atomic(rule_set)

        project_repository.mark_rule_ready(
            project.project_id,
            rule_set_path=rule_path,
        )
        return project_repository.get(project.project_id)

    except Exception as exc:
        project_repository.mark_rule_failed(project.project_id, exc)
        raise
```

### 5.2 分批规则抽取

```python
async def extract_rule_candidates(project_id, parsed_documents):
    candidates = []

    for document in parsed_documents:
        for batch in build_stable_context_batches(document.sections):
            prompt = render_prompt(
                "rule_extraction",
                project_id=project_id,
                source_context=build_source_context(document.document, batch),
                output_schema=RuleExtractionBatch.model_json_schema(),
            )
            response = await invoke_structured(
                model=rule_extraction_model,
                messages=[SystemMessage(content=prompt)],
                output_type=RuleExtractionBatch,
                mode=settings.rule_extraction_model.structured_output_mode,
            )

            # LLM 输出中的来源引用必须能映射回本批输入。
            candidates.extend(
                validate_and_attach_sources(response.rules, batch)
            )
    return candidates
```

### 5.3 规则合并

```python
def merge_rule_items(candidates):
    normalized = [normalize_rule(item) for item in candidates]
    groups = group_by_semantic_key(
        normalized,
        keys=["category", "target_field", "scope.package_no", "scope.material_name"],
    )

    merged = []
    for group in groups:
        if all_requirements_equivalent(group):
            merged.append(
                combine_sources(select_primary_rule(group), group)
            )
        elif precedence_can_resolve(group):
            winner = choose_by_source_precedence(group)
            merged.append(
                winner.with_supporting_sources(other_sources(group))
            )
        else:
            merged.append(
                build_conflict_rule(
                    group,
                    status="rule_conflict",
                    conflict_note=describe_conflict(group),
                )
            )
    return merged
```

### 5.4 来源优先级

```python
SOURCE_PRIORITY = {
    "package_goods_list": 40,
    "special_technical_spec": 30,
    "tender_special_terms": 20,
    "general_terms": 10,
}

def choose_by_source_precedence(group):
    ranked = sorted(
        group,
        key=lambda item: SOURCE_PRIORITY[item.source_kind],
        reverse=True,
    )
    # 只有来源类别和作用域足以确定优先级时才能自动选择。
    return require_unambiguous_highest_priority(ranked)
```

## 6. Prompt 要求

- Prompt 正文保存在 `app/prompts/templates/rule_extraction.md`。
- `app/rules/extractor.py` 负责选择章节、构造来源上下文并调用统一 loader。
- 输入中包含文件和章节来源 ID。
- one-shot 只说明抽取格式，不写死本数据集内容。
- 要求抽取项目级和包级 scope。
- 每条规则必须有主要来源。
- 无法确定的字段使用空值或 `manual_review`，禁止编造。

## 7. 测试设计

- 多文件共同生成一个 RuleSet。
- 同一规则在多个文件重复出现时合并并保留来源。
- 640x480 与包级 320x240 冲突按作用域/优先级处理。
- 无法确定优先级时生成 `rule_conflict`。
- 规则抽取失败时 Project 为 `rule_failed`。
- `rule_failed` 项目不能创建审核任务。
- 上传文件同名不会覆盖，来源路径可追溯。

## 8. 验收标准

- 能从示例招标文件生成通过 Schema 的 RuleSet。
- 每条规则包含来源文件、章节和适用范围。
- RuleSet 与 `project_id` 固定绑定。
- 审核执行过程中不重新解析或修改 RuleSet。
